# CLAUDE.md

Guidance for coding agents working in this repository.

## Project Overview

V3 is a two-agent iterative writing coach for grades 5–7, built with LangGraph, explicitly configured DeepSeek thinking mode, Streamlit CCv2, Pydantic, and SQLite. Students select one to three goals, edit their own complete draft, submit immutable revisions, and stop voluntarily with an original-to-final reflection. Use only synthetic writing. This is not production software for minors.

`PRD_V3_ITERATIVE_REVISION.md` is the active product contract. `PRD.md` and the annotated `v1` tag preserve historical V1/V2 coursework and evidence; the old runtime paths have been replaced.

## Current V3 Decisions

- Keep two model-driven agents. The Coordinator owns assessment, genre, source limits, framework coverage, selected-goal observations, comparison findings, human-review flags, routing, and **finding severity classification**. Support owns student-facing round feedback, bounded scaffolds, and final reflection language without adding framework issues.
- Teacher review, clarification, direct response, diffs, milestones, and lifecycle operations are deterministic. Do not add a comparison agent or audience-specific agents without a separate architecture decision.
- Every nonempty draft goes to the Coordinator. Empty drafts are rejected locally. Explicit length limits reject oversized input without truncation.
- Genre selection is `auto`, `argument`, `informational`, or `narrative`. Explicit selections are normalized deterministically; correction reassesses the latest submitted snapshot without a new revision snapshot or clarification confirmation.
- Optional framework name/component inputs support CER, RACE, RACES, MEAL, and explicit custom lists. Coordinator returns one coverage entry per required component; present entries need exact located references and issue entries need existing goal IDs.
- V3 has no affect field or check-in. **Show less feedback** and **I’m stuck** only reveal pregenerated presentation content; they make no model call and never infer emotion, effort, or teacher review. Choose initially shows one recommended goal with a choose-only action; alternatives are revealed on request and grouped by idea/reasoning/organization versus optional sentence polishing.
- Source availability is deterministic. Source-dependent findings require locations; no-source accuracy claims and invented source content are invalid. Support receives full source text only for source-dependent findings or limitations.
- **Every issue requires a `finding_severity` classification (accuracy | reasoning | development). On initial and revision routes, the Coordinator orders accuracy first, a draft-supported student concern next, and remaining issues by severity/pedagogical priority. Python performs only a stable accuracy partition and otherwise preserves Coordinator order; it does not re-sort non-accuracy issues or add a concern field.** The v3.8.0 Coordinator contract no longer requests `reasoning_operation`; its only consumer was the removed sentence-starter feature. Clearly imaginative system features are not fabricated evidence merely because they are invented; assess process clarity and coherence without certifying technical effectiveness or imposing irrelevant source requirements.
- Every candidate reference must be an exact current-draft substring with correct paragraph/occurrence metadata. A unique exact issue reference with an invalid location receives recorded deterministic normalization; analogous recovery applies only to `status="present"` framework coverage and logs framework/component identity separately. Ambiguous, repeated, missing, and cross-paragraph references still require bounded repair. Support must preserve Coordinator references and source limitations exactly. Final references are never normalized.
- Hints contain a passage reference, 3–5 total steps (one concept restatement followed by 2–4 procedural steps), and a self-check. The local v3.8.3 runtime retains the v3.8.0 schema without generated vocabulary options, sentence starters, or their output fields; legacy v3.7.x evaluation arms retain separate models and prompts. Completion blanks and completion ellipses in instructional fields trigger bounded repair. An ellipsis in an exact quoted draft excerpt used only for locating is not a completion placeholder. Structural validation does not replace semantic authorship review. V3 does not generate optional practice exercises in round feedback.
- Coordinator model flag categories exclude `clarification_limit`; only the deterministic graph owns that internal category after two unclear answers. A model-selected value is neutralized rather than honored or relabeled as concerning content. Clarification and teacher-review routes return empty ordinary assessment collections; teacher review may also leave all genre metadata empty.
- `SUPPORT_ROUND_CONSOLIDATED_PROMPT` remains an evaluation-only `v3.7.2-consolidated` candidate selected by `support_consolidated`. `BASELINE_READABLE_*_PROMPT` forms the preserved `v3.8.1-baseline-readable` candidate selected by `baseline_readable`. `BASELINE_READABLE_V2_*_PROMPT` forms the evaluation-only `v3.8.2-baseline-readable` candidate selected by `baseline_readable_v2`. `REGRESSION_READABLE_*_PROMPT` preserves the `v3.8.3-regression-readable` evaluation control selected by `regression_readable`. Following the owner's explicit promotion decision, the default `COORDINATOR_*_PROMPT` and `SUPPORT_ROUND_PROMPT` use local `v3.8.3` with the same behavioral guidance and `LOCAL RUNTIME CONTRACT` labels; `STRUCTURAL_*_PROMPT` preserves v3.8.0 for `structural_current`. The student runtime does not switch prompt arms or thinking modes automatically.
- Revision observations cover every selected goal and use descriptive statuses, not scores or attempt assumptions. Optional attempted/deferred self-reports are stored with the revision snapshot.
- The evaluation-only `phase1` arm uses prompt/schema `v3.9.2-phase1`/`v3.9.0` and does not change the promoted student default. It adds separate `goal_outcome` and `narrowing` dimensions, exact previous-draft deletion and task-requirement evidence, deterministic outcome/carry-forward/route consistency, same-ID live candidates, and direct-response `optional_polish`. Support and direct response preserve the full observation contract; neutral UI labels bound outcomes to selected goals. Phase 1 round/history persistence leaves legacy outcomes unknown, does not inject bounded history into every round, does not auto-select carried goals, and does not change Final interpretation or consistency semantics. Development and reserved transfer fixtures are `test_cases/v3/phase1_development.json` and `phase1_transfer.json`; transfer requires explicit candidate freeze and reclassification if used for tuning.
- Final reflection uses deterministic original/latest-submitted diffs and Coordinator finding IDs. At Finish, the service populates declared `revision_history` from persisted snapshots and matching successful Coordinator reviews, including exact goal references, authoritative observations, and draft hashes. Final consistency rejection requires an exact goal-ID/reference link and a matching latest draft hash; deletion rejection requires deletion wording and an exact original reference that remains in Final. Do not infer empty goal IDs or automatically judge semantic weakening. Support cannot omit regressions, add improvements, or change verified references. Original strengths and future possibilities pass through validated Coordinator findings.
- Each agent invocation permits one bounded repair. Coordinator failure after repair falls back to safe clarification; Support/final failure produces no partial feedback. API and thinking-mode failures propagate rather than silently switching modes.

## Architecture

```text
Submitted draft -> Assessment Coordinator -> conditional route
    |- ask_clarification -> interrupt -> answer -> Coordinator
    |- support_agent -> candidates + pregenerated scaffolds -> END
    |- teacher_review -> separate student/evaluator outputs -> END
    `- direct_response -> no manufactured revision -> END

Finish confirmation -> deterministic original/final diff
    -> Coordinator comparison -> Support final reflection -> END
```

`langgraph_core/state.py` uses `TypedDict`/`NotRequired`. Initialize inputs, IDs, model configuration, and execution metadata together. Each node returns only fields it owns. Replacement lists prevent duplicate history during interrupt replay.

`langgraph_core/revision.py` owns exact reference location, word-level diffs, neutral change notifications, draft hashing, and persisted snapshot/review assembly for Final history. It makes no quality judgments.

## Code Organization

- `app.py`: Streamlit entry point and cached V3 runtime.
- `agents/`: DeepSeek HTTP client, V3 prompts, structured Coordinator/Support validation, repair, and authorized model metadata.
- `langgraph_core/`: V3 state, nodes, routing, graph/service operations, and deterministic revision utilities.
- `storage/`: Composition, snapshot, round, reflection, restoration, and deletion persistence.
- `ui/`: Student workflow, scenario loading, CCv2 highlighted editor, and opt-in observability.
- `test_cases/v3/scenarios.json`: Separate versioned V3 synthetic presets. `acceptance.json` contains the 32-scenario acceptance set; `live_el_contrasts.json` contains controlled targeted experiments. Root fixture files remain frozen historical V1/V2 evidence.
- `scripts/evaluate_v3.py`: Real-model evaluation with goal selectors, controlled prefixes, Support-only handoffs, experiment arms, usage/cost records, repair/failure diagnostics, and stable database hashes.
- `tests/`: Mocked unit/integration/AppTest coverage with temporary SQLite databases.

## Model Configuration

- Following the user's explicit decisions, student runtime uses the v3.8.0 structural contract with `DEEPSEEK_THINKING=true`, omits temperature, and includes configured reasoning effort. The thinking-mode selection followed the 2×2 review; the later structural decision did not promote readability/grounding candidate wording. Explicit non-thinking comparisons remain available with temperature 0. No automatic mode switch or non-thinking error fallback occurs.
- Record `model_name`, requested `thinking_enabled`, applicable `reasoning_effort`, prompt/schema/fixture versions, provider IDs, latency, and available token counts. A requested thinking field is not proof that reasoning occurred; report provider reasoning usage only when supplied.
- Evaluation-only SOTA runs use `SOTA_API_KEY`/`SOTA_BASE_URL`/`SOTA_TIMEOUT_SECONDS`; Claude Opus 5.5 uses native Anthropic Messages thinking and Gemini 4 Argon uses native Gemini `generateContent` with `thinkingLevel=HIGH` and `includeThoughts=false`. Protocol-required per-request output fields remain supported.
- Raw hidden reasoning is never stored or displayed. Evaluation diagnostics may retain final prompts and invalid final JSON responses; student debug capture remains separately opt-in.
- Neither mode is a student-facing selector or an automatic fallback.

## Storage and UI Invariants

- Persist original and every revision snapshot before model review. Snapshot updates are prohibited by SQLite trigger; deletion intentionally cascades for **Delete my data**.
- Retry uses the existing round/reflection and never creates a duplicate snapshot.
- Session IDs filter history but are not authentication. Missing/corrupt storage produces a safe recovery view and preserves any runtime editor text for copying.
- Keep the initial editor constrained and the desktop workspace 60/40 while using bounded viewport-relative widths and heights. Marked grid rows must override Streamlit child column widths to 100% to avoid applying percentages twice. Responsive fixed-height containers must also override Streamlit's fixed flex-basis.
- The CCv2 editor takes `data.value` only on first mount; afterward the textarea is the source of truth and only pushes edits to Session State. Do not reintroduce `data.value` → `editor.value` sync on re-render: stale echoes during fast typing scramble characters (fixed in `90023ab`; focus checks and debounces did not work). Verify editor input changes with real per-key typing (`page.keyboard.type`), not `fill()`. The editor highlights exact selected references, groups identical/nested/transitive overlaps with textual goal labels, recalculates on edits, and drops stale highlights rather than relocating them.
- Header step navigation and dialog cancellation preserve the editor and existing feedback. Completed steps reflect actual saved actions, not step order. Evaluator reveal controls require `SHOW_EVALUATION_CONTROLS=true`; each panel remains independently hidden until selected. The final comparison uses submitted snapshots, never unsubmitted editor text, and renders them as escaped keyboard-focusable read-only regions.

## Safety, Privacy, and Evidence

The UI warning is: "Do not submit writing containing real names, schools, or personal information. This is a demo system — your input is sent to an external AI service."

Writing, assignment/source context, concerns, clarification answers, selected goals, self-reports, and diffs may be sent to DeepSeek and stored in SQLite. Session filtering is not secure multi-user isolation. Teacher handoff is simulated: no teacher is notified. Never invent crisis resources or diagnose students.
